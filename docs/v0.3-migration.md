# Migrating from v0.2 to v0.3

RPA Core v0.3 changes execution vocabulary without changing execution
semantics. Update application code and machine-record consumers together. No
compatibility aliases are provided for the retired Python names.

| v0.2 | v0.3 |
| --- | --- |
| `Skill`, `rpacore.skill` | `Step`, `rpacore.step` |
| `SkillReport` | `StepReport` |
| `Transaction.skills` | `Transaction.steps` |
| `ordered_skills()`, `failed_skills()` | `ordered_steps()`, `failed_steps()` |
| exception `datetime_occurred` | `occurred_at` |
| `stop` / `stops_execution` | `halts_remaining_steps` |
| history/transition/log `skill_*` fields and events | corresponding `step_*` fields and events |
| generated `skills/` package | generated `steps/` package |

Generic Python and automation terms remain unchanged, including `arguments`,
`exceptions`, `BusinessException`, `SystemException`, `Status.SUCCESSFUL`, and
`execution_order`.

Machine-readable consumers must accept the new versions and shapes:

| Contract | v0.3 version |
| --- | --- |
| Canonical transaction | 3 |
| Report | 2 |
| Execution transition | 2 |
| CLI transaction list/show | 2 |
| JSON/NDJSON export | 2 |
| JSON log | 3 |
| Doctor | 1 (transaction schema support is 10) |
| Query cursor | 1 |

JSON logging no longer accepts a format-version selector; format v3 is the sole
JSON log output. Update processors for the protected envelope and nested
`attributes` object.

Transaction SQLite schema v9 migrates forward to v10 when opened through a
write-capable framework path. The migration preserves transaction and child
records while translating the table, columns, and history events listed above.
Stop workers and back up transaction and queue databases together before the
upgrade. Queue schema remains version 4. Read-only inspection never migrates.

After updating an automation, keep its `definition_identity` unchanged only if
the renamed step classes still represent the same recoverable work and durable
state interpretation. Otherwise use a new identity and start a new transaction.
